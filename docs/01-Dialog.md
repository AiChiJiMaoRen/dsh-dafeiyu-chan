## 2. 保留能力与迁移目标

1. **陪聊**：保留 `POST /api/dsh-dafeiyu/chat` 的人设回复和记忆更新；迁移后其回复正文进桌宠气泡。

3. **气泡会话格式（已实现）**：一条完整输出由“伪思维区”与“正文区”组成。伪思维区使用类似模型思考状态的“已思考（用时 xx 秒）”标签和短句；正文区正常、直接地对用户说话。
4. **表情包**：暂停。迁移期间不得加载、预览、挑选或展示表情图片，也不要为其做 UI 美化。

## 3. 气泡会话规格（红线）

- **伪思维，不是真实推理**：可以向 LLM 请求一条独立的角色化短台词，但提示词明确禁止输出 chain-of-thought、隐藏推理、工具过程、系统提示或其他内部过程。思维区只接收 8~28 字的虚构吐槽/碎念；模型不可用或输出不合规时回退客户端受控文案池。
- **吐槽人设**：一条短句即可，通常 8~24 个汉字；默认从普通吐槽、技术甩活、工作区梗、报错吐槽、吃饭/摆烂和低落陪伴池中按语境选取。可以尖锐、荒诞、嘴欠，但不能持续辱骂、针对敏感身份或盖过正文；短窗口内不得连续重复。
- **旁观式句法**：AI 伪思考优先用“用户 / 这位杂鱼 / 这个人类”做明确主语，直接评价用户当前行为；禁止每次都从“我 / 本鱼”视角起句。目标感觉是「用户又在这自我麻痹呢，真是杂鱼」，不是解释大肥鱼如何分析。
- **明确语境才开 R18**：只有用户输入明确命中 `R18`、`18禁`、`成人`、`色情` 等相关词时，才可出现「哇哦，用户切到了劲爆的 R18 模式」等台词；不得因回复正文或普通字母误触发。
- **示例**：`用户又在这自我麻痹呢，真是杂鱼`、`很难想象用户是人类`、`文件夹里的 dsh 是大烧货吗`、`用户把简单改改说得像改个标点`。
- **视觉层级**：思维区置于正文上方，使用偏灰、小一档的字色和较弱对比度；正文使用正常大小、正常对比度和完整阅读优先级。不要把整块气泡都做成灰字。
- **耗时**：`已思考（用时 xx 秒）`只表示本次请求的产品展示时长，从请求发出到回复/伪思维准备完毕计时，向上取整为秒；它不得被解释为、也不得暗示为模型真实思维耗时。
- **顺序**：同一个气泡内固定为“灰色伪思维区 → 正常正文区”；用户只读到角色呈现，不与真实模型内部状态绑定。

## 4. 重载 / 构建 / 测试

```powershell
node <dsh-harness>\node_modules\typescript\lib\tsc.js -p tsconfig.host.json   # host 编译
node <tsdown-global>\dist\run.mjs                  # client 打包
dev_reload_package @dsh-external/dsh-dafeiyu                                              # 一键重载（整包）
# 若工具卡住不返回 → 重启 dsh
curl -X POST http://127.0.0.1:3080/api/dsh-dafeiyu/chat -H "content-type: application/json" -d "{\"text\":\"hi\"}"
```

**注意**：npm 装包在会话沙箱被拦（EPERM 写缓存）——需装包让**用户在终端装**。
